# 设计约定

本文描述第一版设计与行为约束。实现与验证状态见 `verification.md`。第一版优先减少首次连接步骤，并保证后台隧道的可恢复性。

## 主界面

0.6 界面约定：保留约 560 × 740 的黑灰紧凑窗口，红色为操作强调；小面积状态文字区分成功、重连和失败，不添加延迟探测、网格纹理或额外统计。

1. 首页：未配置时只有虚线添加卡片；配置完成后才显示服务器卡片、功能条、长条圆角矩形连接按钮和状态。没有常驻侧栏和输入表单。
2. 点击服务器卡片打开选择页，可新增、切换；首次使用卡片直接进入设置。
3. 点击「编辑连接」打开设置页；名称、地址、端口、认证统一编辑，「保存并返回」回到首页。
4. 命令导入与 ComfyUI 设置收在编辑页的折叠区域，默认不展开。
5. 连接成功后才显示本地地址与「复制地址」「打开 ComfyUI」。断开后隐藏。
6. 日志由首页底部入口打开独立页面。各二级页面均提供返回按钮。

首次未配置时主按钮为「添加服务器」；未保存密码且本次未输入时，连接按钮打开设置页并提示密码字段，不发起无凭据的连接。编辑页返回暂存草稿，保存才持久化；既有加密存储格式不变。

窗口外框采用轻微圆角，卡片约 8 DIP、普通控件约 6 DIP，避免大圆钮与窗口外框不协调。

首页使用 ComfyUI 功能条与拨动开关，设置页使用同步的复选框，默认关闭，按配置独立加密保存。已连接时禁用模式修改，断开后可切换。未启用时不绑定本地端口、不发送 TCP 转发请求，也不发出 HTTP 探测，仅保持 SSH 会话；本地地址为空。目标地址和端口字段在此模式下不参与连接校验。旧配置没有该字段时按关闭处理，升级后需自行勾选。

仅 SSH 模式依赖 SSH/TCP 错误与断开检测；KeepAlive 只用于保活，静默断链可能等待系统 TCP 超时。启用 ComfyUI 时保留既有通道请求超时与 HTTP 目标探测。

表单采用「主机信息 / 认证方式」两组，密码与私钥为一体分段控件。聚焦显示柔和外环，错误显示边框和字段下方文字，并定位第一个错误字段；错误所在折叠区域自动展开。地址、端口、命令采用系统等宽字体，其余保留系统中文字体，不捆绑额外字体。输入占位符只作示例，不替代字段标签。

折叠标题整行可点击，具有悬停反馈和旋转箭头。页面切换淡入约 150ms，同页验证失败不重复淡入。连接与重连主按钮显示水平进度反馈，操作分别为「取消」「取消重连」；已连接使用暗底描边，失败为「重试」并显示原因。页面淡入和持续进度动效尊重 Windows 客户区动画设置。`Ctrl+S` 仅在设置页可保存时生效。

每条配置有稳定 ID，名称可重复。切换时暂存表单草稿，停止旧连接，清理旧重试；不自动连接新 VPS。异步状态更新带 UI 代际检查，旧连接事件不能覆盖新配置状态。保存与连接会持久化列表；未保存的草稿仅在当前进程内保留。收起 ComfyUI 面板不停止转发。

详细诊断默认折叠。界面不展示实现框架、SSH 库或后台线程等技术细节。密码和私钥口令默认不保存，用户可以明确选择保存。

关闭窗口隐藏到托盘。首次关闭时以非阻塞提示说明程序仍在运行。托盘提供「显示窗口」「连接/断开」「退出」。第一版不自动开机启动，也不自动启动上次隧道；用户下次打开后可一键连接。

## SSH 命令输入

计划支持的最小语法：

```text
ssh ubuntu@gpu.example.com
ssh -p 12345 ubuntu@gpu.example.com
ssh -p12345 -l ubuntu gpu.example.com
ssh -i "C:\Keys\gpu key" -p 12345 ubuntu@gpu.example.com
```

- `ssh` 可带 `.exe` 后缀。支持域名、IPv4 和明确括起的 IPv6；IPv6 的实际输入与地址格式必须测试。
- 默认 SSH 端口为 `22`。未提供用户名时要求用户填写，不猜测远端账号。
- 参数顺序、引用路径和 Windows 反斜杠由解析器处理，不使用按空格简单分割。
- 只支持显式白名单参数：`-p`、`-l`、`-i`。其他选项说明暂不支持，不自动执行或忽略。
- 不支持 SSH config 别名展开、跳板链、`-J`、`-o`、`-L/-R/-D` 或命令末尾远端操作。若用户需要，后续单独设计。
- 重复或冲突参数应要求用户修正，避免隐藏的覆盖规则。
- 端口为 `1–65535`；空主机、缺失参数、未闭合引号、管道及命令组合均需明确报错。
- 解析失败不覆盖上次有效配置，不触发连接。

## 地址与转发

SSH 服务器与目标服务分别建模：

```text
SSH 入口：gpu.example.com:12345，用户 ubuntu
目标服务：127.0.0.1:8188（从 SSH 服务端访问）
本地监听：127.0.0.1:18188（或自动分配的可用端口）
```

目标服务可以改为 SSH 服务端可达的容器或内网地址。无需在应用里管理容器、KVM、ComfyUI 进程。

本地端口自动模式优先尝试 `18188`，不可用时通过实际绑定分配其他可用端口，避免预扫描和实际绑定之间的竞态。固定模式占用时直接提示用户。最终监听成功后才显示本地地址。

同一次连接的自动恢复保留已分配端口。手动断开后重新连接才允许在自动模式下重新分配端口。

默认本地 URL 为 `http://127.0.0.1:<实际端口>/`。第一版面向默认 HTTP ComfyUI；远端 HTTPS、路径前缀等配置暂不纳入。

## 状态与自动恢复

对用户暴露：未连接、连接中、已连接、正在重连、连接失败。认证等待与指纹确认可显示具体说明。

内部还应区分：用户希望保持连接与用户要求断开。只有前者允许自动恢复。每次新连接建立独立生命周期标识，使旧回调无法改变新状态。

- 连接尝试设置超时，默认建议 `15` 秒；每一步均可取消。
- 网络故障采用有上限的指数退避，例如约 `2 / 4 / 8 / 16 / 30` 秒，并加入小幅抖动。
- 网络恢复和系统唤醒可以提前唤醒重试，但不得产生并行连接流程。
- 稳定连接一段时间后重置退避计数，避免反复短连接造成高频重试。
- 身份认证失败、主机指纹变化、配置错误和固定端口冲突不自动无限重试。
- 当前使用 SSH keepalive 维持空闲流量，配合经过本地转发的 HTTP 探测。SSH 通道建立超过超时、传输错误或连接失效触发恢复；仅 HTTP 响应超时不触发重建。已测试 TCP 黑洞场景，但仍需验证真实服务器不同的目标连接超时行为。

已连接表示 SSH 会话和本地转发已建立，不保证 ComfyUI 已就绪。通过同一隧道进行有超时、低频的 HTTP 探测，给出「服务可访问」「目标暂不可达」等补充信息；不触发生成任务，不把未知的 HTTP 响应误判成身份已确认的 ComfyUI。

服务不可达时保留健康 SSH 隧道，让远端 ComfyUI 启动后能够直接访问。显式断开应取消全部重试和探测，并释放连接与监听。

## 配置、身份与日志

- 默认保存于当前用户应用数据目录下的项目专属子目录；具体目录名随正式应用名确定。
- 配置含版本字段，采用临时文件加替换的原子写入方式；损坏配置给出恢复提示，不静默覆盖。
- 私钥默认留在用户指定位置；不复制到应用目录，不修改原始私钥。
- `connections.dat` 和 `known-hosts.dat` 整体使用 Windows DPAPI CurrentUser 加密，包括配置元数据与指纹；临时文件也只写密文。密码/口令仅在用户选择记住时持久化；换电脑或用户后不能直接解密这些文件。
- 兼容旧版单配置 JSON，成功写入新密文后移除旧文件；遇到无法解密或损坏的文件拒绝覆盖。私钥原文件不复制也不重新加密。
- 主机指纹绑定 SSH 主机地址与端口，首次确认、后续校验。变化后只能通过明确核实流程更新。
- 日志记录状态变化、经过脱敏的失败原因和重试时间，不记录认证内容及完整粘贴文本。
- 日志限制单文件大小和保留数量，建议最多 `5 × 2 MiB`；UI 日志条数也必须有上限。

## 技术与分发

实现模块：WPF UI、配置/凭据存储、SSH 命令解析器、SSH.NET 转发适配层、连接控制器、诊断日志。

程序提供通用本地 HTTP 入口，不与浏览器绑定。支持 ComfyUI Desktop 或本机 API 客户端填写该入口，透明传输 HTTP/WebSocket/媒体。程序不重放请求，不重新提交生成任务，不承担工作流和产物管理。

采用维护中的 .NET 版本，自包含发布为 Windows x64 单文件。原生组件可自动解压，用户不需要额外安装依赖。依赖版本、运行时版本、单文件设置和第三方声明在实现时固定并记录。

第一版运行在用户登录会话中。程序退出、Windows 注销或关机都会停止隧道；睡眠后恢复仅在进程仍存活时自动执行。隧道恢复不会恢复已经断开的上层会话，也不保证远端任务状态。


0.6 功能条关闭时显示仅 SSH；开启后显示配置映射和待连接状态。绑定成功后使用实际本地端口，自动选择其他端口时也正确更新；重连时显示待恢复。表单取消包围所有字段的外层边框，以间距分组；滚动条视觉宽约 4 DIP，但保留 10 DIP 命中区域。
